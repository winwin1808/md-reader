Goal: core can read the text of Y.Text "source" as it was at any history checkpoint that carries a Yjs snapshot (8x: checkpoints have `clientIds` + snapshot since phase 6). Core can also restore that text as a minimal delta, recording a new history entry.

### [x] 8g1.1 — restore.ts
FILES       packages/core/src/doc/restore.ts (new) · packages/core/src/doc/restore.test.ts (new) · packages/core/src/index.ts
INTERFACES  Read these existing core files to find the real names and shapes:
            - schema.ts for `HistoryEntry` and its snapshot field, which is an encoded Y snapshot of type Uint8Array or a base64 string. Decode it accordingly.
            - apply.ts for `applyTextChange` and the ORIGIN_* constants, including `ORIGIN_REVERT`.
            - history.ts / checkpoint.ts for `appendHistory`, or whatever function appends an entry to Y.Array "history".
            produces (re-exported from index.ts):
            export function textAtCheckpoint(doc: Y.Doc, entry: HistoryEntry): string | null
            export function restoreCheckpoint(doc: Y.Doc, entry: HistoryEntry, actor: string): boolean
BEHAVIOR    textAtCheckpoint:
            - If the entry has no snapshot, return null.
            - Otherwise decode it, build `Y.createDocFromSnapshot(doc, snapshot)`, and return `.getText('source').toString()`.
            - Destroy the temporary doc afterwards.
            - If decoding or creation throws, return null.
            restoreCheckpoint:
            - Get the text via textAtCheckpoint. If it is null, return false.
            - If it equals the current text, return true with no write and no history entry.
            - Otherwise call applyTextChange(doc, text, ORIGIN_REVERT), which writes the minimal delta, then append a history entry labelled `Khôi phục: <entry.label>` with the given actor. Use the existing append path, so clientIds and snapshot are filled the same way as for other checkpoints.
            - Return true.
INVARIANTS  - packages/core is pure TS. It may use yjs, but no react, chrome.* or document, and it never knows a provider.
            - The schema is unchanged: Y.Text "source", Y.Map "meta", Y.Array "history". formatVersion is not bumped.
            - Docs are gc:false. createDocFromSnapshot needs that, so do not change doc creation.
            - Writes to Y.Text always go through applyTextChange (minimal delta), never delete-all + insert.
TEST        pnpm --filter @md-reader/core test src/doc/restore.test.ts must cover:
            - Create a doc with the project's factory, write "A", and checkpoint (entry1). Write "AB" and checkpoint (entry2). Write "ABC". Then textAtCheckpoint(entry1) is "A" and textAtCheckpoint(entry2) is "AB".
            - After restoreCheckpoint(entry1, 'An'), the text is "A". The transaction origin seen by `doc.on('afterTransaction')` is ORIGIN_REVERT. The minimal delta is checked by counting deleted chars, which must be 2 (only "BC" deleted, not a full rewrite). The last history entry's label is 'Khôi phục: <entry1 label>' and its actor is 'An'.
            - Restoring to the current text returns true and appends no history.
            - An entry without a snapshot returns null and false.
            - A corrupted snapshot returns null and false, and does not throw.
            Then pnpm --filter @md-reader/core test (full count) and pnpm --filter @md-reader/core typecheck.
COMMIT      feat(core): textAtCheckpoint + restoreCheckpoint (8g1)

### [x] 8g1.2 — restore through the caller's tracker (no duplicate 'auto' entry)
FILES       packages/core/src/doc/restore.ts · packages/core/src/doc/restore.test.ts · packages/core/src/doc/checkpoint.ts
INTERFACES  restoreCheckpoint(doc: Y.Doc, entry: HistoryEntry, actor: string, tracker?: CheckpointTracker): boolean
            - `CheckpointTracker` is the type returned by createCheckpointTracker. Export it if it is not exported yet.
            - Widen the `flush()` label parameter in checkpoint.ts from 'save' | 'auto' | 'import' to `string`. HistoryEntry.label is already a string. Remove the cast in restore.ts.
BEHAVIOR    When `tracker` is given (the app's long-lived tracker):
            1. `tracker.flush('auto', actor)` (non-forced), so earlier pending edits get their own entry first. It is a no-op when nothing is pending.
            2. `applyTextChange(getSource(doc), text, ORIGIN_REVERT)`.
            3. `tracker.flush('Khôi phục: <label>', actor, { force: true })`. This clears the tracker's pending clients and timer, so it never writes a later duplicate 'auto' entry for the revert.
            Without `tracker`, keep the current temporary-tracker path. Document in a comment that callers with a live tracker must pass it.
            Do not make the tracker ignore ORIGIN_REVERT globally, because useFileSave's reload-from-disk relies on it.
INVARIANTS  - packages/core is pure TS. It may use yjs, and must not use react, chrome.* or document.
            - The schema is unchanged. History entries keep `clientIds` and the snapshot exactly as other checkpoints do.
            - Writes to Y.Text go only through applyTextChange (minimal delta).
            - Existing checkpoint tests pass unchanged.
TEST        pnpm --filter @md-reader/core test src/doc/restore.test.ts must cover:
            - Live tracker passed, no duplicate: restore, then advance past quietMs (use fake timers) and call `tracker.flush('auto', 'x')`. History grows by exactly 1 (the 'Khôi phục' entry).
            - Pending earlier edits: one entry for them ('auto'), then the restore entry, in that order.
            - A mixed insert+delete restore case: from "Xin chào bạn" back to "Xin bạn", and from "A" forward to "AB" via an earlier checkpoint. Assert the text, and assert that the inserted and deleted lengths are minimal.
            - The corrupt-snapshot case also asserts that the source text and history length are unchanged.
            Then run pnpm --filter @md-reader/core test (full count) and pnpm --filter @md-reader/core typecheck.
COMMIT      fix(core): restoreCheckpoint dùng tracker của app, không sinh mốc 'auto' trùng (8g1)
