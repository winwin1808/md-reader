BEHAVIOR    privacy-policy.md: keep the existing structure and tone. Replace every "no server / nothing leaves your device" absolute with this model:
            - By default all data stays on the device (IndexedDB, chrome.storage).
            - Data leaves the device only when the user turns on sharing for one document. Then that document's content, the self-declared display names of the people editing it, and link metadata (role, expiry, revoked flag, token hashes — never raw tokens) are sent to the collaboration server the user configured.
            - Retention: until the owner turns sharing off or revokes links. Say exactly what turning sharing off deletes, from the code. If the code only revokes and does not delete the room state, say that honestly.
            - Live presence (name, colour, cursor) is relayed and not stored.
            - No analytics, no tracking, no ads, no sale of data. No accounts.
            - The server operator is whoever runs the configured Worker URL.
            - Add an updated date of 2026-10-24.
            listing.md: add a "Chia sẻ" paragraph in VI and its EN counterpart, 2–4 sentences each:
            - share a view link or an edit link
            - edit together live, with names and cursors
            - see who wrote which line
            - sharing is optional and off by default
            Remove or soften any "không cần máy chủ / no server" claim, so it reads e.g. "works fully offline; sharing is optional".
INVARIANTS  - Copy is in Vietnamese, sentence case, no emoji. The EN section mirrors the VI one.
            - Server stores only SHA-256 hashes of tokens; view links cannot write; expired or revoked links get 410. No R2 or KV.
            - Never paste a real token, account id or URL containing a secret. A placeholder like https://<your-worker>.workers.dev is fine.
            - Do not invent features that the code does not have.
