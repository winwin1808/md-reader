# Plan: Phase 8 — 8c1b Collaboration settings and sync status
Author: Hao Nguyen. Status: building. Phase: 8. Sub-phase: 8c1b
Spec: docs/superpowers/specs/2026-10-24-phase-8-design.md
Branch: phase-8-8c1b-collab-settings
BranchPoint: 13315b7

Goal: Settings gets a "Cộng tác" tab with the server address and the display name. The toolbar shows
the sync state of a shared document as text: Đang kết nối / Đã đồng bộ / Ngoại tuyến. App feeds both
settings into useShare and useDocSession, which 8c1a left on constants.

Decisions recorded here:
- `packages/ui` cannot import the extension's `DEFAULT_SERVER_URL`, so SettingsModal takes it as a
  prop (`defaultServerUrl`) and shows it as the placeholder. An empty field means "use the default".
- An invalid server address is never used: App passes `normalizeServerUrl(settings.serverUrl) ??
  DEFAULT_SERVER_URL`. The field shows a hint while invalid. A room that already exists keeps its
  own serverUrl (from its binding); the setting only affects new rooms.
- When offline, y-partyserver retries with backoff 100 ms → 2.5 s and the status flips offline →
  connecting → offline on every retry (8c1a review). The toolbar smooths it: after 'offline', a
  'connecting' shorter than 1500 ms keeps showing "Ngoại tuyến".
- `ui` declares its own `SyncStatus` union, identical to the extension's, because ui cannot import
  from apps/extension.

            - Status is shown as words, not color alone (Lề sách: trạng thái bằng chữ).
