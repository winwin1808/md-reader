INTERFACES  consume from @md-reader/core: applyTextChange, ORIGIN_LOAD, hashText.
            DocSession gains exactly:
              externalChange: { remoteText: string; remoteHash: string } | null
              acceptExternal(): void     // applyTextChange(yText, remoteText, ORIGIN_LOAD); meta originHash = remoteHash; clear
              dismissExternal(): void    // clear only
            Load algorithm for ?file= (replaces "import whenever fetched"):
              1. fetch/cached remote text as today (cache key, XHR for file:, GitHub blob rewrite);
              2. `await persistence.whenSynced` (y-indexeddb) BEFORE reading or writing yText;
              3. h = await hashText(remote); local = yText.toString(); origin = meta.get('originHash');
                 - local === ''                → import (applyTextChange … ORIGIN_LOAD) + meta originHash = h + name as today;
                 - origin === h                → keep the doc untouched (local edits preserved), isDirty = (await hashText(local)) !== origin;
                 - (await hashText(local)) === origin → no local edits: apply remote (ORIGIN_LOAD), meta originHash = h;
                 - otherwise                   → externalChange = { remoteText: remote, remoteHash: h }; touch nothing.
              The "synced" handler must not overwrite content set by step 3 (keep isFileContentSetRef semantics).
            App: when session.externalChange, render inside the existing `.error-banner`
              container: text "File gốc đã thay đổi kể từ lần mở trước." and two buttons
              "Tải bản mới" (acceptExternal) and "Giữ bản đang sửa" (dismissExternal).
            App (review 6c follow-up): handleFormatAction's view.dispatch gets back
              `scrollIntoView: true`.
INVARIANTS  - Never silently merge disk/URL content into a Y.Doc that has unsaved local edits;
              never write Y.Text before y-indexeddb has synced.
            - Writes to Y.Text are minimal deltas (applyTextChange) with origin 'md:load' for imports.
            - apps/extension owns the provider (y-indexeddb); core stays provider-agnostic.
            - Import other packages by workspace name only.

### [x] 6d.2 — save reports real states; conflict does not re-open
FILES       apps/extension/src/app/hooks/useFileSave.ts
            apps/extension/src/app/hooks/useFileSave.test.tsx
            apps/extension/src/app/App.tsx
INTERFACES  FileSave gains exactly: `saveAs(): Promise<void>` — always opens the Save As
            picker (same path as the no-handle branch of save), then saves.
            saveState transitions:
              - start of save → { kind:'saving' }
              - success → { kind:'saved', at: Date.now() }
              - handle.getFile() or .text() throws → { kind:'error', message:'Không đọc được file trên đĩa (đã bị xoá hoặc di chuyển?).', canSaveAs:true }
                and NO conflict modal, text untouched
              - write throws → { kind:'error', message: <error.message or 'Không ghi được file.'>, canSaveAs:true }
              - Save As picker cancelled (saveFileAs returns null) → { kind:'idle' }
              - disk hash ≠ originHash → { kind:'conflict' } + modal open
            closeConflict(): closes the modal but keeps saveState { kind:'conflict' };
            while kind === 'conflict' the autosave effect does nothing; an explicit save
            re-runs the check. keepLocal() acquires the same isSavingRef guard as save and
            releases it in finally, and saves with explicit = true (the user chose to
            overwrite, so format-on-save applies — review 6c follow-up).
            App: when saveState.kind === 'error', render inside `.error-banner` the message
            plus a "Lưu thành…" button (when canSaveAs) calling fileSave.saveAs().
INVARIANTS  - A failed disk read is an error, never a conflict and never an empty "disk" version.
            - Never write to disk while a conflict is unresolved, except via keepLocal().
            - Writes to Y.Text are minimal deltas (applyTextChange).
            - Import other packages by workspace name only.
TEST        pnpm --filter extension test src/app/hooks/useFileSave.test.tsx
            Add cases: (1) getFile rejects → state error with canSaveAs, conflict.open false,
            yText unchanged; (2) successful save → kind 'saved'; (3) conflict → closeConflict →
            advance fake timers 2000ms with dirty → no write and modal stays closed;
            (4) cancelled picker → 'idle'; (5) keepLocal while a save is in flight does not
            write twice. Then `pnpm --filter extension test` once; report total.
COMMIT      fix(extension): honest save states, no conflict re-open loop, Save As action
