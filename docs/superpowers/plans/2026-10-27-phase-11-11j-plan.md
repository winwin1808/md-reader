Sự thật đã kiểm: máy chủ MCP (11i) gửi `hello{protocol:2, client, serverKey, nonce}`, chờ `auth{extKey, nonce, sig}` (sig = ký `authPayload('ext', hello.nonce, keyId(serverKey), port)`),
trả `auth-ok{sig}` (ký `authPayload('srv', auth.nonce, keyId(extKey), port)`) hoặc `reject{DENIED}`; ghim extKey TOFU trong 10 phút đầu. Helper ở `@md-reader/core/bridge-auth`
(`generateBridgeKeyPair, exportPublicKey, importPublicKey, exportPrivateJwk, importPrivateJwk, keyId, fingerprint, newNonce, authPayload, signPayload, verifyPayload`); kiểu ở `@md-reader/core/bridge`.
Extension hiện (v1): `apps/extension/src/worker/bridge.ts` `onHello` băm `pairKey` → `keyHash` (64 hex), so `deps.approved()` → gửi `welcome`; chưa duyệt → `requestPairing({port, client, keyHash})`
→ worker/index.ts:134 mở `app.html?pair=<port>&client=..&key=<keyHash>` → `main.tsx` `PairPage` → `PairDialog` (packages/ui) → `PAIR_DECISION_MSG` → `bridge.decide(port, allow, add, keyHash)`.
`ApprovedClient { keyHash, client, at }` (bridge-storage.ts). Chỉ hello `protocol === BRIDGE_PROTOCOL` (=1) được xử lý (bridge.ts ~122).
Quyết định: `keyHash` giữ tên/định dạng (64 hex) nhưng giờ = `keyId(serverKey)` → trang duyệt + Settings dùng lại; mục duyệt v1 cũ không khớp → ghép cặp lại (chưa phát hành).

### [x] T1 — Worker: bắt tay v2, ghim khoá máy chủ, khoá extension
FILES       apps/extension/src/worker/bridge.ts · apps/extension/src/worker/bridge.test.ts · apps/extension/src/worker/bridge-storage.ts · apps/extension/src/worker/bridge-storage.test.ts · apps/extension/src/worker/index.ts
INTERFACES  - bridge-storage.ts: `ApprovedClient { keyHash: string; client: string; at: number; serverKey: string }` (parse bỏ mục thiếu `serverKey`).
              `export const BRIDGE_KEY_STORAGE = 'mdr.bridgeKey'`; `export async function loadOrCreateExtKey(store: StoreLike): Promise<{ privateKey: CryptoKey; publicKey: string }>`
              (JWK riêng + SPKI công khai lưu trong store; hỏng → tạo mới).
            - bridge.ts: `BridgeDeps` thêm `extKey(): Promise<{ privateKey: CryptoKey; publicKey: string }>`. `BridgeConn.state: 'pending' | 'authing' | 'paired'`.
              Chỉ xử lý hello `protocol === 2` (v1 → đóng). onHello: `kid = await keyId(h.serverKey)`; lưu `serverKey`, `serverNonce` vào entry; `keyHash = kid`.
              Đã duyệt (`approved` có `keyHash === kid && serverKey === h.serverKey`) → `authenticate(e)`; chưa → state pending + `requestPairing({ port, client, keyHash: kid })`.
              `authenticate(e)`: `myNonce = newNonce()`; `sig = signPayload(priv, authPayload('ext', e.serverNonce, kid, e.conn.port))`; gửi `{type:'auth', extKey: pub, nonce: myNonce, sig}`; state 'authing'.
              Nhận `auth-ok` khi 'authing': `verifyPayload(importPublicKey(e.serverKey), authPayload('srv', myNonce, await keyId(pub), port), sig)` → 'paired'; sai → close + drop.
              Nhận `reject` → close + drop. `decide(port, allow, add, keyHash)`: allow → `add({ keyHash, client, at, serverKey })` rồi `authenticate(e)` (KHÔNG gửi welcome). Bỏ mọi `welcome`.
              `onReq` chỉ khi 'paired' (giữ). `revoke(keyHash)` giữ.
            - index.ts: truyền `extKey: () => loadOrCreateExtKey(chrome.storage.local)` (memo một promise).
INVARIANTS  - Chỉ `apps/extension` dùng `chrome.*`. Không thêm dependency; helper từ `@md-reader/core/bridge-auth`.
            - Không thực thi `req` trước khi `auth-ok` của máy chủ được xác minh bằng khoá máy chủ đã ghim (người dùng duyệt).
            - Không log khoá riêng; không gửi bí mật qua dây.
TEST        pnpm --filter extension test src/worker/bridge.test.ts src/worker/bridge-storage.test.ts (đỏ trước; máy chủ giả dùng helper core thật:
            (a) hello v2 chưa duyệt → requestPairing với keyHash = keyId(serverKey), không gửi auth; (b) decide allow → gửi auth có chữ ký verify được bằng extKey với payload port đúng;
            (c) auth-ok hợp lệ → req được thực thi; auth-ok ký sai/khoá khác → đóng, req không thực thi; (d) đã duyệt nhưng serverKey khác (cùng client) → không auth, requestPairing;
            (e) hello v1 → đóng; (f) loadOrCreateExtKey: lần 2 trả cùng publicKey). Cập nhật test v1 cũ. Sau đó `pnpm --filter extension test` xanh.
