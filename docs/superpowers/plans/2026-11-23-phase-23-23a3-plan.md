### [x] 23a3-1 — Tuỳ chọn render `sourcePositions` gắn `data-sp` lên phần tử khối
parallel-group: a3
FILES       packages/core/src/render/types.ts, packages/core/src/render/render.ts, packages/core/src/parse/sanitize-schema.ts, packages/core/src/render/render-options.test.ts
INTERFACES
```ts
// RenderOptions (đang khai ở src/render/types.ts hoặc options.ts — sửa đúng nơi khai báo) thêm:
sourcePositions?: boolean   // mặc định false
```
Hành vi:
- Khi `sourcePositions: true`: mọi phần tử hast sinh từ node mdast khối `paragraph`, `heading`, `listItem`, `blockquote`, `code`, `table`, `tableRow`, `thematicBreak`, `math`, và `html` (sau sanitize) có thuộc tính `data-sp="<position.start.offset>:<position.end.offset>"` — offset trong chuỗi Markdown gốc truyền vào render (KHÔNG phải sau khi bóc frontmatter; nếu render bóc frontmatter trước khi parse thì cộng độ dài phần bị bóc để offset vẫn tính theo source gốc). Cách làm gợi ý: plugin remark gán `node.data.hProperties.dataSp` cho các node khối có `position` trước bước remark→rehype; node `code` được highlight/mermaid thay thế thì gắn lên phần tử ngoài cùng sinh ra (`pre` hoặc khối mermaid).
- Schema sanitize (`sanitize-schema.ts`) cho phép thuộc tính `dataSp` trên các thẻ `p, h1-h6, li, blockquote, pre, table, tr, hr, div` và chỉ chấp nhận giá trị khớp `^\d+:\d+$` (dùng dạng `['dataSp', /^\d+:\d+$/]` của hast-util-sanitize). Giá trị `data-sp` do người dùng viết trong HTML thô với dạng khác bị loại. Lưu ý: HTML thô do người dùng viết `<p data-sp="1:2">` khớp regex sẽ lọt qua — chấp nhận (chỉ ảnh hưởng neo bình luận của chính tài liệu đó), ghi vào NOTES.
- `sourcePositions` không bật → HTML ra y hệt trước (snapshot hiện có trong `render.test.ts` / `__snapshots__` không đổi; KHÔNG cập nhật snapshot).
- Thứ tự plugin: plugin đã chạy trước sanitize với `clobberPrefix` — `data-sp` không được bị thêm tiền tố clobber (nó không phải id/name).

- Parser là `unified`/`remark`, re-parse toàn bộ (không parse tăng tiến). Không đổi parser, không thêm dependency.

- rehype plugin chạy trước sanitize + `clobberPrefix`; sanitize là ranh giới XSS — chỉ mở đúng thuộc tính `dataSp` với regex số.

### [x] 23a3-2 — Ánh xạ vùng chọn chữ → offset source
parallel-group: a3
FILES       packages/core/src/comments/anchor-map.ts (mới), packages/core/src/comments/anchor-map.test.ts (mới), packages/core/src/index.ts
INTERFACES  (produce, export từ `@md-reader/core`)
```ts
export interface SourceBlock { start: number; end: number }
export function parseSourcePos(attr: string | null): SourceBlock | null
export function selectionToSourceRange(
  source: string, block: SourceBlock, selectedText: string, occurrence: number,
): { from: number; to: number; exact: boolean }
```
Hành vi:
- `parseSourcePos`: `"12:40"` → `{start:12,end:40}`; null, rỗng, sai dạng, `start > end`, số âm/không nguyên → null.
- `selectionToSourceRange`: kẹp `block` vào `[0, source.length]`. `seg = source.slice(block.start, block.end)`.
  1. Tìm lần xuất hiện thứ `occurrence` (0-based) của `selectedText` trong `seg` → `{from: block.start+i, to: from+len, exact: true}`. Nếu có ít hơn `occurrence+1` lần nhưng ≥ 1 lần → dùng lần cuối, vẫn `exact: true`.
  2. Không thấy → so khớp lỏng: dựng bản "chữ hiển thị" của `seg` bằng cách bỏ ký tự đánh dấu `*`, `_`, `~`, `` ` ``, bỏ `[` và phần `](…)` của link/ảnh, gộp mọi chuỗi khoảng trắng thành một dấu cách; giữ mảng ánh xạ chỉ số chữ-hiển-thị → chỉ số trong `seg`. Chuẩn hoá `selectedText` (gộp khoảng trắng, trim). Tìm lần thứ `occurrence` (hoặc lần cuối) → ánh xạ đầu/cuối về `seg` → `exact: true`.
  3. Vẫn không thấy, hoặc `selectedText` trim rỗng → `{from: block.start, to: block.end, exact: false}`.
  - Kết quả luôn thoả `block.start <= from < to <= block.end` khi block khác rỗng.
- Thuần, không throw với mọi input.
INVARIANTS
- `packages/core` thuần TS: KHÔNG react, `chrome.*`, `document`/`window` — hàm nhận chuỗi, không nhận DOM (UI sẽ đọc DOM rồi gọi hàm này ở sub-phase sau).
- Không thêm dependency.
- Export qua `src/index.ts` bằng đường dẫn tương đối đuôi `.js` như các export khác.
TEST        pnpm --filter core test src/comments/anchor-map.test.ts && pnpm --filter core typecheck
Test phải chứng minh: đoạn thường (exact); chữ nằm trong `**đậm**` (chọn "đậm" → trỏ đúng chữ không gồm `**`); chọn "a **b** c" xuyên dấu đậm (khớp lỏng, from/to bao trọn `a **b** c`); link `[nhãn](http://x)` chọn "nhãn"; mục danh sách; ô bảng; chữ lặp hai lần với occurrence 1 → lần thứ hai; occurrence vượt quá → lần cuối; không khớp → cả khối `exact:false`; `parseSourcePos` các ca hợp lệ/không hợp lệ.
COMMIT      feat(core): ánh xạ vùng chọn chữ về offset Markdown nguồn
