            ```sql
            CREATE TABLE usage_daily (scope TEXT NOT NULL, subject TEXT NOT NULL, day INTEGER NOT NULL, kind TEXT NOT NULL,
              n INTEGER NOT NULL DEFAULT 0, PRIMARY KEY (scope, subject, day, kind));
            CREATE TABLE room_installs (room_id TEXT PRIMARY KEY, install_hash TEXT NOT NULL, bytes INTEGER NOT NULL DEFAULT 0);
            CREATE INDEX room_installs_install ON room_installs (install_hash);
            CREATE TABLE reports (id INTEGER PRIMARY KEY AUTOINCREMENT, room_id TEXT NOT NULL, reason TEXT NOT NULL,
              ip_hash TEXT NOT NULL, created_at INTEGER NOT NULL);
            CREATE TABLE takedowns (room_id TEXT PRIMARY KEY, created_at INTEGER NOT NULL);
            ```
            apps/api/src/limits.ts:
            ```ts
            import type { LimitErrorCode } from '@md-reader/core'
            export const LIMITS = {
              roomsPerInstallPerDay: 20, roomsPerIpPerDay: 50, roomsGlobalPerDay: 500, liveRoomsPerInstall: 200,
              assetsPerInstallPerDay: 100, assetBytesPerInstall: 200 * 1024 * 1024, reportsPerIpPerDay: 10,
            } as const
            export type LimitKind = 'room' | 'asset' | 'report'
            export interface LimitSubject { installHash: string | null; ipHash: string }
            export type LimitVerdict = null | { error: LimitErrorCode; retryAfter?: number }
            export interface LimitStore {
              check(kind: LimitKind, s: LimitSubject, info?: { roomId?: string; bytes?: number }): Promise<LimitVerdict>
              record(kind: LimitKind, s: LimitSubject, info: { roomId: string; bytes?: number }): Promise<void>
            }
            export function dayOf(now: number): number                 // Math.floor(now / 86_400_000)
            export function secondsToNextDay(now: number): number      // Math.ceil(((dayOf(now)+1)*86_400_000 - now)/1000)
            export function subjectFrom(req: Request): Promise<LimitSubject>
            export class MemoryLimitStore implements LimitStore { constructor(now?: () => number) }
            export class D1LimitStore implements LimitStore { constructor(db: D1Database, now?: () => number) }
            ```
            `subjectFrom`: `installHash` = SHA-256 hex của header `x-mdr-install` nếu header có và dài 16..200 ký tự, ngược lại null;
            `ipHash` = SHA-256 hex của `CF-Connecting-IP` (vắng → chuỗi `'unknown'` rồi hash). Dùng `hashToken` từ `./tokens.js`.
            Luật `check` (dừng ở vi phạm đầu tiên; RATE_LIMITED kèm `retryAfter = secondsToNextDay(now)`; QUOTA_EXCEEDED không có retryAfter):
            - room: global ngày ≥ 500 → RATE_LIMITED; ip ngày ≥ 50 → RATE_LIMITED; nếu installHash: install ngày ≥ 20 → RATE_LIMITED;
              số dòng `room_installs` của install ≥ 200 → QUOTA_EXCEEDED.
            - asset: tra install của `info.roomId` trong room_installs; không có → null (phòng cũ/không khoá: chỉ quota 50 MB/phòng sẵn có áp).
              Có → install ngày (kind asset) ≥ 100 → RATE_LIMITED; tổng `bytes` các phòng của install + `info.bytes` > 200 MiB → QUOTA_EXCEEDED.
            - report: ip ngày (kind report) ≥ 10 → RATE_LIMITED.
            Luật `record`:
            - room: +1 cho (global,'*'), (ip,ipHash), và nếu installHash: (install,installHash) ngày hôm nay kind room; chèn room_installs(roomId, installHash, 0) nếu installHash.
            - asset: nếu phòng có trong room_installs: +1 (install, hash) kind asset, cộng `bytes` vào room_installs.bytes của phòng.
            - report: +1 (ip, ipHash) kind report.
            D1: đếm bằng `INSERT INTO usage_daily (scope,subject,day,kind,n) VALUES (?,?,?,?,1) ON CONFLICT(scope,subject,day,kind) DO UPDATE SET n = n + 1`; nhiều câu ghi gộp `db.batch`.
INVARIANTS  `apps/api` chạy trên Workers: KHÔNG `document`/`window`, KHÔNG `chrome.*`; import core bằng `@md-reader/core`, không bao giờ đường dẫn tương đối sang package khác.
            Máy chủ chỉ lưu hash của khoá bản cài và IP — không bao giờ lưu/log giá trị thô.
            Gói Workers Free: không KV/R2/rate-limit binding; chỉ D1 + DO.
            `packages/core/src/share/share.ts` chỉ thêm hai export, không đổi export sẵn có.
TEST        pnpm --filter api test src/limits.test.ts   (test chạy trên MemoryLimitStore với `now` giả; D1LimitStore chỉ cần typecheck: `pnpm --filter api typecheck`)
COMMIT      feat(api): LimitStore theo bản cài/IP/toàn cục + migration 0003

### [x] 10c.2 — Nối giới hạn vào `POST /api/rooms` và upload ảnh
FILES       apps/api/src/api.ts · apps/api/src/index.ts · apps/api/src/api.test.ts
INTERFACES  Tiêu thụ từ 10c.1: `LimitStore`, `subjectFrom`, `D1LimitStore`, `LimitVerdict`.
            `ApiDeps` thêm `limits?: LimitStore`. Trong `handleApi`:
            - `POST /api/rooms`: nếu `deps.limits`: `s = await subjectFrom(req)`; `v = await deps.limits.check('room', s)`; v → 429;
              tạo phòng; rồi `await deps.limits.record('room', s, { roomId })`; trả 201 như cũ.
            - `POST /api/rooms/:roomId/assets`: sau mọi kiểm hiện có (quyền, mime, kích thước, sniff, quota phòng 50 MB) và TRƯỚC `assets.put`:
              `check('asset', s, { roomId, bytes })` → 429; sau `put` thành công: `record('asset', s, { roomId, bytes: size })`.
            - Body 429: `{ error: v.error, retryAfter?: number }`; khi có `retryAfter` thêm header `retry-after: <giây>`.
            index.ts: truyền `limits: new D1LimitStore(env.DB)` trong deps của `handleApi`; thêm `x-mdr-install` vào
            `access-control-allow-headers` (giữ nguyên các header đang có); thêm `retry-after` vào `access-control-expose-headers` trong `withCors`.
            Không có `deps.limits` → hành vi y hệt hiện tại (test cũ không đổi).
INVARIANTS  Không đổi status/body của các route khác; test cũ trong api.test.ts phải xanh nguyên.
            Kiểm giới hạn phải chạy SAU kiểm quyền (request không quyền vẫn 401/403, không tiêu quota) và `record` chỉ sau khi ghi thành công.
            `apps/api`: KHÔNG `document`/`window`/`chrome.*`; import core bằng `@md-reader/core`.
