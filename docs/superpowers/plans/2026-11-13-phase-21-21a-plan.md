### [x] 21a.1 — `hello` nhận `pinnedExt` tuỳ chọn + `bridgePinState`
FILES       packages/core/src/bridge/protocol.ts · packages/core/src/bridge/protocol.test.ts
INTERFACES  Sinh ra (export từ `protocol.ts`, nên có sẵn qua `@md-reader/core/bridge`):
            ```ts
            export interface BridgeHello {
              type: 'hello'; protocol: 2; client: string; serverKey: string; nonce: string
              /** undefined = máy chủ cũ (không biết) · null = chưa ghim · 64-hex = keyId khoá extension đã ghim */
              pinnedExt?: string | null
            }
            export type BridgePinState = 'unknown' | 'none' | 'self' | 'other'
            export function bridgePinState(pinnedExt: string | null | undefined, myKeyId: string): BridgePinState
            ```
            `parseBridgeMessage` nhánh `'hello'`: các kiểm tra hiện có giữ nguyên. Thêm: `o.pinnedExt === null` → kết quả có `pinnedExt: null`; `typeof o.pinnedExt === 'string'` và khớp `/^[0-9a-f]{64}$/` → kết quả có `pinnedExt` đó; mọi trường hợp khác (vắng, số, chuỗi sai dạng, hex hoa) → kết quả KHÔNG có thuộc tính `pinnedExt` (`'pinnedExt' in result === false`) và `hello` vẫn hợp lệ.
            `bridgePinState`: `undefined` → `'unknown'`; `null` → `'none'`; `=== myKeyId` → `'self'`; còn lại → `'other'`.
INVARIANTS  `packages/core` thuần TS: không react, không `chrome.*`, không `document`/`window`.
            Tương thích ngược: `hello` của `le-sach-mcp@1.3.2` (không có `pinnedExt`) phải parse ra đúng như trước — test hiện có của `hello` không được sửa kỳ vọng.
            `pinnedExt` chỉ là gợi ý hiển thị: giá trị rác không được làm `parseBridgeMessage` trả `null`.
            Không đổi `BRIDGE_PROTOCOL` (vẫn 2), không đổi message nào khác, không đổi `MCP_PACKAGE_SPEC` (việc của 21e2).
