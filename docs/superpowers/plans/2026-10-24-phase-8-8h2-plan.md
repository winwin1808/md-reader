            export interface PageRender { html: string; title: string | null }
            export function renderMarkdownForPage(markdown: string): PageRender
            Message: `{ action: 'renderMd', markdown: string }` → sendResponse(`{ ok: true, html, title }` | `{ ok: false, error: 'too-large' | 'bad-request' | 'render-failed' }`)
BEHAVIOR    renderMarkdownForPage:

            - Respond synchronously and do not return true for this branch.
            - The openApp branch is unchanged.

            - The worker has no DOM. Do not use document or window.

            export interface PageRender { html: string; title: string | null }
            export function requestPageRender(markdown: string, timeoutMs = 4000): Promise<PageRender | null>  // chrome.runtime.sendMessage({ action: 'renderMd', markdown }); null on ok:false, lastError, missing chrome.runtime, or timeout
            ContentApp.tsx: ContentAppProps gains `render?: PageRender | null` and `onShowRaw?(raw: boolean): void`. Existing exports stay.
BEHAVIOR    index.ts:
            - Unchanged up to markdownText, the settings and the alwaysOpenApp hand-off.
            - Before mounting, `const render = await requestPageRender(markdownText)`.
            - If render is non-null:
              - mount the root in reading layout (rootEl gets attribute data-mode="read")
              - hide the page's source node(s) the text came from (the `<pre>`, or body children other than #md-reader-root) by setting style.display='none', and remember their previous inline display
              - onShowRaw(true) restores them and sets data-mode="raw"; onShowRaw(false) hides them again and sets data-mode="read"
              - if render is null, do exactly what happens today (tab only)
            - The ErrorBoundary's restore also un-hides the source nodes.
            ContentApp:
            - When `render` is given, render a reader:
              - `<header class="bar">` holds the BookIcon, the title (or "Tài liệu Markdown"), button "Đọc trong MD Reader" (openInApp, same as today, with the same error handling and FAIL_TEXT) and a toggle button "Xem bản thô" / "Xem bản đọc" that calls onShowRaw.
              - Below it, `<article class="doc">` with `dangerouslySetInnerHTML={{ __html: render.html }}` (the html was sanitized by the worker). It is hidden while in raw mode.
            - Without `render`, keep today's tab UI and behavior unchanged, so the 6 existing tests stay green.
            content.css:
            - :host[data-mode="read"] is not fixed. It is a normal block, max-width about 46rem, centered, with page margins.
            - :host[data-mode="raw"] shows only the bar, sticky at the top.
            - Keep the existing :host tab rules for the no-render case, scoped so they don't apply when data-mode is set.
            - Reader typography: headings, p, lists, blockquote, table (100% width, borders), pre/code (monospace, scroll), img max-width, GitHub alert boxes (the class names render.ts emits; check a render-md test output or render.ts), and code.language-math / code.language-mermaid placeholders styled as a dashed box with a ::before label "Công thức — mở trong MD Reader để xem" / "Sơ đồ — mở trong MD Reader để xem".
            - Light and dark via prefers-color-scheme. Plain CSS custom properties defined on :host. Hex is allowed here, because the content script can't use the app's token file.
INVARIANTS  - The content script never imports yjs, @md-reader/ui or @md-reader/core. It only messages the worker.
            - The content.js gz budget: check-size 61440; report the measured value; review blocks above 50 KB.
            - All page DOM changes are reversible: "Xem bản thô" and the ErrorBoundary restore bring the page back exactly.
            - Never send markdown anywhere except chrome.runtime.sendMessage to our own worker.
