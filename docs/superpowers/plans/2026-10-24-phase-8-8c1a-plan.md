# Plan: Phase 8 — 8c1a WebSocket provider in the extension
Author: Hao Nguyen. Status: built. Phase: 8. Sub-phase: 8c1a
Spec: docs/superpowers/specs/2026-10-24-phase-8-design.md
Branch: phase-8-8c1a-provider
BranchPoint: f365562

Goal: once a doc has a room (sharing is on), the app page binds its Y.Doc to the room through
`y-partyserver`'s YProvider, next to y-indexeddb. Enabling sharing therefore uploads the document,
and view links stop showing an empty page. The session exposes `syncStatus` and `awareness` for
8c1b (toolbar text) and 8d (presence).

Decisions recorded here:
- `useDocSession` takes the room from its caller (`opts.room`, App passes `share.binding`), not from
  the registry record, so enabling sharing mid-session binds immediately without a reload.
- The provider is created only after IndexedDB `whenSynced`, so local state goes first and the
  server receives the full local doc in the first sync step.
- Display name in 8c1a is the constant "Bạn"; the setting arrives in 8c1b. Awareness carries
  `user: { name }` only; color arrives in 8d2.
- The provider authenticates with the owner token in the `token` query param (the Worker resolves an
  owner token to role 'edit').

FILES       apps/extension/src/app/collab/bindRoom.ts (new) · apps/extension/src/app/collab/bindRoom.test.ts (new) · apps/extension/package.json · pnpm-lock.yaml
INTERFACES  Add dependency `"y-partyserver": "2.2.0"` to apps/extension (same version as apps/api), then `pnpm install`.
            consumes: `wsHost(serverUrl): string` and `API_PATHS.party` (= 'doc-room') from `@md-reader/core`; `SyncStatus = 'off' | 'connecting' | 'online' | 'offline'` from `../../shared/collab`; `YProvider` from 'y-partyserver/provider'; `Awareness` type from 'y-protocols/awareness' (import type only; if y-protocols is not resolvable from apps/extension, type it as `YProvider['awareness']`).
            produces:
            export interface BindRoomOptions { serverUrl: string; roomId: string; token: string; name: string }
            export interface RoomConnection {
              provider: YProvider
              awareness: Awareness
              status$(cb: (s: SyncStatus) => void): () => void   // calls cb immediately with the current status; returns unsubscribe
              destroy(): void
            }
            export function bindRoom(doc: Y.Doc, opts: BindRoomOptions, deps?: { Provider?: typeof YProvider }): RoomConnection
BEHAVIOR    - `new Provider(wsHost(serverUrl), roomId, doc, { party: API_PATHS.party, params: { token }, connect: true })`. If serverUrl starts with `http://` also pass the option that forces plain `ws` (check YProvider's option type in node_modules/y-partyserver for the exact name, e.g. `protocol: 'ws'`); https uses wss.
            - Status: starts 'connecting'. Provider 'status' event `{status:'connected'}` keeps 'connecting' until the 'synced' event fires with true → 'online'. `{status:'disconnected'}` → 'offline'. A later reconnect goes 'connecting' → 'online' again. Emit only on change.
            - `awareness.setLocalStateField('user', { name })` right after construction.
            - destroy(): unsubscribe all listeners, `provider.destroy()`, status becomes 'off' (emitted once), further destroy() calls are no-ops. It must NOT destroy the Y.Doc.
INVARIANTS  - packages/core never imports a provider; choosing and attaching the provider is apps/extension's job.
            - Y.Doc (Yjs) is the source of truth; the file is import/export only. The provider is attached to the same Y.Doc that y-indexeddb persists.
            - The Y.Doc never carries tokens: the owner token goes only into the WebSocket URL params, never into Y.Map "meta" or awareness.
            - Raw tokens are never logged.
            - The content script must not import this module (Yjs is forbidden there).

Cover: ctor receives host from wsHost('https://x.workers.dev') = 'x.workers.dev', room id, the same doc, party 'doc-room', params.token; awareness user name set; status sequence connecting → (connected) connecting → (synced true) online → (disconnected) offline → (synced) online; subscriber gets current status on subscribe; unsubscribe stops calls; destroy calls provider.destroy once, emits 'off', doc is not destroyed (doc.isDestroyed false or a 'destroy' listener not fired), second destroy no-op. ### [x] 8c1a.4 — bindRoom: offline on failed first connect, no leaked socket (review fix)
FILES       apps/extension/src/app/collab/bindRoom.ts · apps/extension/src/app/collab/bindRoom.test.ts
INTERFACES  bindRoom signature unchanged. Behavior:
            - y-partyserver only emits status 'disconnected' when the socket had opened. A socket that closes or errors before opening emits only 'connection-close' / 'connection-error'. Listen to both: if the current status is 'connecting', set 'offline'. A later 'status connected' or 'synced true' must still move to 'connecting'/'online' as today. Remove these listeners in destroy().
            - YProvider.connect() is async (it awaits param resolution, then enables reconnect). Guard against destroy() racing it: construct with `connect: false`, then call `provider.connect()` yourself; when that promise settles, if destroy() already ran, call `provider.disconnect()` again (and swallow a rejection). The ctor args recorded by tests change from `connect: true` to `connect: false`; update that assertion.
INVARIANTS  - packages/core never imports a provider; only apps/extension attaches providers.
            - destroy() must never destroy the Y.Doc.
            - Raw tokens are never logged.
            - Existing bindRoom status-sequence tests keep passing (except the connect flag assertion noted above).
TEST        pnpm --filter extension test src/app/collab/bindRoom.test.ts — extend FakeProvider with an async `connect()` returning a controllable promise and a `disconnect` spy. Add: emitting 'connection-close' while connecting → 'offline'; emitting 'connection-error' while connecting → 'offline'; after that, 'status connected' + 'synced true' → 'online'; destroy() before connect() resolves, then resolve it → disconnect called after resolution and status stays 'off'. Then pnpm --filter extension test (full count) and pnpm --filter extension typecheck (exit code captured directly).
COMMIT      fix(extension): bindRoom báo Ngoại tuyến khi kết nối đầu thất bại, chặn socket rò (8c1a review)
