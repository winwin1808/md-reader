### [ ] 1b1.2 — tsconfig base + vitest root + script workspace

Agent: `builder` (sonnet). Không TDD (task config; cổng là lệnh chạy thật).

```
FILES       package.json           (sửa: thêm devDependencies + script)
            tsconfig.base.json     (mới)
            vitest.config.ts       (mới)
            pnpm-lock.yaml         (sinh ra bởi pnpm install)
            pnpm-workspace.yaml    (ĐỌC để xác nhận, KHÔNG sửa — đã đúng)

INTERFACES  tsconfig.base.json — không có `include`/`files`, đây là base để
              package extends. Đúng những option này, không thêm:
                {
                  "compilerOptions": {
                    "target": "ES2022",
                    "lib": ["ES2022"],
                    "module": "ESNext",
                    "moduleResolution": "bundler",
                    "strict": true,
                    "noUncheckedIndexedAccess": true,
                    "verbatimModuleSyntax": true,
                    "declaration": true,
                    "skipLibCheck": true,
                    "esModuleInterop": true,
                    "forceConsistentCasingInFileNames": true,
                    "noEmit": true
                  }
                }
              KHÔNG khai `paths` — resolution đi qua workspace link của pnpm.
              Đó là thứ khiến vi phạm ranh giới package lộ ra lúc build thay vì
              bị tsconfig che.

            vitest.config.ts — một project cho cả workspace:
                import { defineConfig } from 'vitest/config'
                export default defineConfig({
                  test: { projects: ['packages/*', 'apps/*'], passWithNoTests: true },
                })
              `passWithNoTests` là bắt buộc: 1b1 chưa có package nào, và
              `pnpm test` phải xanh ở phase con này.
              LEVER nếu vitest 5 báo `test.projects` không phải option hợp lệ:
              thay bằng file `vitest.workspace.ts` chứa
              `export default ['packages/*', 'apps/*']` và giữ
              `passWithNoTests` trong `vitest.config.ts`. Chỉ dùng lever khi
              lệnh thật báo lỗi, không dùng phòng xa.

            package.json — giữ nguyên `name`, `private`, `packageManager`
              (`pnpm@10.10.0` đã pin, KHÔNG đổi). Thêm:
                "devDependencies": { "typescript": "^7.0.2", "vitest": "^5.0.0" }
                "scripts": {
                  "test": "pnpm -r test",
                  "typecheck": "pnpm -r typecheck",
                  "build": "pnpm -r build",
                  "test:core": "pnpm --filter @md-reader/core test",
                  "test:ui": "pnpm --filter @md-reader/ui test",
                  "test:extension": "pnpm --filter @md-reader/extension test"
                }
              Ba script `test:*` tồn tại vì tên package có scope
              (`@md-reader/core`) còn `CLAUDE.md` ghi lệnh `pnpm --filter core
              test`. 1b2 sẽ kiểm xem pnpm có giải được filter bỏ scope không;
              ba script này là đường chắc chắn đúng trong lúc chờ.

            Cài bằng: pnpm add -Dw typescript@^7.0.2 vitest@^5.0.0

INVARIANTS  - Stack khoá cứng: pnpm workspaces · Vite · React · TypeScript ·
              Chrome MV3 · vitest · yjs + y-indexeddb · unified/remark. Không
              đề xuất framework, parser hay test runner khác.
            - Import chéo package luôn bằng tên workspace (`@md-reader/core`),
              KHÔNG bao giờ đường dẫn tương đối (DESIGN.md §2.4). Vì thế
              tsconfig KHÔNG khai `paths`.
            - `packages/core` thuần TS, `packages/ui` React không `chrome.*`,
              `apps/extension` là lớp duy nhất dùng `chrome.*`. Task này không
              tạo package nào — chỉ dựng base mà chúng sẽ extends.
            - Ngân sách: `pnpm -r test` phải xanh ở CUỐI 1b1 dù chưa có
              package nào (DESIGN.md §4, điều kiện của 1b).

TEST        pnpm install
            pnpm exec tsc --version          → in 7.x (ghi số thật vào báo cáo)
            pnpm exec tsc --noEmit -p tsconfig.base.json 2>&1 | head -5
              → nếu TS7 từ chối option nào, nó lộ ở đây. Base config không có
                `include` nên tsc có thể báo "No inputs were found" — đó là
                CHẤP NHẬN ĐƯỢC và phải ghi rõ trong báo cáo; lỗi về
                *option không hợp lệ* thì KHÔNG chấp nhận được → dùng lever
                hạ typescript về ^6.0.3 rồi chạy lại.
            pnpm test                        → exit 0 (chưa có package)
            pnpm typecheck                   → exit 0 (chưa có package)
            pnpm exec vitest run             → exit 0, "no test files found"
                                               kèm passWithNoTests

COMMIT      chore: tsconfig base, vitest root, script workspace
```
