### [x] 6a.1 — computeTextChanges + applyTextChange + origin constants
FILES       packages/core/src/doc/apply.ts (new)
            packages/core/src/doc/apply.test.ts (new)
INTERFACES  produce, exactly:
            export interface TextChange { index: number; deleteCount: number; insert: string }
            export function computeTextChanges(prev: string, next: string): TextChange[]
            export function applyTextChange(yText: Y.Text, next: string, origin?: unknown): boolean
            export const ORIGIN_LOAD = 'md:load'
            export const ORIGIN_FORMAT = 'md:format'
            export const ORIGIN_REVERT = 'md:revert'
            Behaviour:
            - computeTextChanges: strip the common prefix and common suffix (suffix must
              not overlap the prefix), then run Myers O((N+M)·D) shortest edit script over
              UTF-16 code units of the two middles; merge adjacent delete/insert runs into
              TextChange records. If D would exceed 2000, return a single change replacing
              the whole middle. Result is sorted by ascending `index`, indexes refer to
              positions in `prev`, changes do not overlap. prev === next → [].
            - applyTextChange: prev = yText.toString(); if prev === next return false and
              do NOT open a transaction. Otherwise apply the changes from LAST to FIRST
              (so earlier indexes stay valid) with yText.delete / yText.insert inside ONE
              `yText.doc!.transact(() => { ... }, origin)` and return true. If yText has no
              doc, apply without transact.
INVARIANTS  - packages/core is pure TypeScript: it may import `yjs`, but never react, chrome.*,
              document/window, or any Yjs provider (y-indexeddb, y-websocket…).
            - Y.Text "source" is the source of truth; writes must be the minimal delta —
              never `delete(0, length)` followed by `insert(0, text)`.
            - Every core/doc feature has a convergence test: two Y.Docs edited separately,
              synced both ways with Y.encodeStateAsUpdate / Y.applyUpdate, must end equal.
            - Tests run in vitest, node environment; no DOM.
TEST        pnpm --filter core test src/doc/apply.test.ts
            Cases required:
            1. property test: ~200 seeded-random (prev,next) pairs (deterministic PRNG in
               the test, alphabet incl. "a", "\n", "ư", "ệ" written as e + combining dot
               (U+0065 U+0323 U+0302), and an emoji "📖"): applying computeTextChanges(prev,next)
               to prev (as plain string ops, last→first) yields next; and applyTextChange on a
               Y.Text seeded with prev yields next.
            2. equal strings: applyTextChange returns false and the doc emits no 'update'.
            3. attribution: docA inserts "hello world" (client A); docB (synced copy) calls
               applyTextChange(text, "hello there world"); after syncing back, every char of
               "hello " and " world" is still authored by A's clientID (inspect via
               Y.Text items: walk `text._start` → `.right`, collect `item.id.client` for
               non-deleted items with their content length; cast through `any`).
            4. convergence/no-duplication: shared start "* a\n* b\n"; replica A
               applyTextChange → "- a\n- b\n"; replica B concurrently
               applyTextChange → "* a\n* b\n\nc"; sync both ways; both equal "- a\n- b\n\nc".
            5. large middle: prev/next of 50k random chars each → returns a single change
               (D cap) and still converts prev to next.
COMMIT      feat(core): minimal-delta applyTextChange for Y.Text
