# Plan: Phase 8 — 8b4 extension share wiring
Author: Hao Nguyen. Status: planned. Phase: 8. Sub-phase: 8b4
Spec: docs/superpowers/specs/2026-10-24-phase-8-design.md
Branch: phase-8-8b4-extension-share
BranchPoint: c8c42b5

Goal: the "Chia sẻ" button on the app page opens ShareModal. Turning sharing on creates a room on
the server and stores the binding in the doc registry. Creating, listing, copying and revoking view
links works against the real API. The Worker also serves apps/web as static assets, with a root
deploy script.

Decisions recorded here:
- **CORS on /api/\*.** The app page runs on a chrome-extension:// origin, so its fetch to the server is
  cross-origin. Phase 6 kept permissions minimal and the server URL is configurable, so we do not add
  host_permissions. Instead the API answers with `Access-Control-Allow-Origin: *`. This is safe
  because auth is a bearer header, never a cookie. WebSocket (/parties/\*) is not subject to CORS.
- **Content upload is 8c1.** After 8b4, "Bật chia sẻ" creates an empty room. The document reaches the
  server once 8c1 binds the WebSocket provider. A view link opened before then shows an empty page.
- **Server URL** is `DEFAULT_SERVER_URL` in 8b4. The settings field arrives in 8c1. The binding stores
  its own serverUrl and every call uses that.
- **The pipeline does not deploy.** 8b4.4 adds the script and checks the config with a dry run. The
  API must be redeployed (`pnpm deploy:api`) for CORS to be live; ship-and-handover does that.

### [ ] 8b4.2 — useShare hook + registry room + DEFAULT_SERVER_URL
FILES       apps/extension/src/shared/collab.ts (new) · apps/extension/src/app/doc-registry.ts · apps/extension/src/app/collab/useShare.ts (new) · apps/extension/src/app/collab/useShare.test.ts (new)
INTERFACES  consumes from `@md-reader/core`: `RoomBinding { serverUrl; roomId; ownerToken }`, `ShareLink`, `CreateLinkRequest`, `CreateRoomResponse { roomId; ownerToken }`, `API_PATHS` (`rooms` = '/api/rooms' POST no auth; `links(roomId)` GET list / POST create, header `Authorization: Bearer <ownerToken>`; `revoke(roomId, prefix)` DELETE, same header).
            From doc-registry.ts (existing): `interface DocRecord { docId; title; originKind; originPath; persistenceName; lastOpenedAt; hasHandle; shortKey? }`, `getRecord(docId): Promise<DocRecord|null>`, `touchRecord(docId, patch?: Partial<Omit<DocRecord,'docId'>>): Promise<void>`.
            produces:
            // src/shared/collab.ts
            export const DEFAULT_SERVER_URL = 'https://md-reader-api.qhao-work.workers.dev'
            export type SyncStatus = 'off' | 'connecting' | 'online' | 'offline'
            // doc-registry.ts: DocRecord gains `room?: RoomBinding` (optional; old records stay valid, no migration needed since the field is optional)
            // src/app/collab/useShare.ts
            export function useShare(opts: { docId: string | null; serverUrl: string }): {
              binding: RoomBinding | null
              links: ShareLink[]
              enable(): Promise<RoomBinding>
              createLink(req: CreateLinkRequest): Promise<ShareLink>
              revoke(prefix: string): Promise<void>
              refresh(): Promise<void>
              busy: boolean; error: string | null
            }
BEHAVIOR    - On docId change: load `getRecord(docId)?.room` into binding (null if none or docId null); links reset to [].
            - enable(): POST `${serverUrl}${API_PATHS.rooms}` → CreateRoomResponse; binding = { serverUrl, roomId, ownerToken }; `touchRecord(docId, { room: binding })`; return it. If binding already exists, return it without a request. docId null → reject with Error('Chưa có tài liệu').
            - refresh(): GET links with bearer → links (server list has token ''). Keep the raw token of any link created this session: merge by tokenPrefix so a known token is not overwritten by ''.
            - createLink(req): POST JSON body → ShareLink with token; prepend to links; return it.
            - revoke(prefix): DELETE → remove the row from links.
            - All calls use `binding.serverUrl` (not opts.serverUrl) once bound. busy is true while any call is in flight.
            - Errors: fetch throws → 'Không kết nối được máy chủ'; 401 → 'Không có quyền với phòng này'; other non-ok → 'Máy chủ trả lỗi <status>'. Set `error`, then reject with an Error of that message. A successful call clears error.
            - Use `globalThis.fetch` at call time (tests assign `globalThis.fetch = vi.fn()`).
INVARIANTS  - apps/extension is the only layer allowed chrome.*; this hook needs none (registry is IndexedDB).
            - Cross-package imports by workspace name only (`@md-reader/core`, `@md-reader/ui`).
            - The Y.Doc never carries tokens: ownerToken lives only in the local registry record, never in Y.Map "meta".
            - Raw tokens and share URLs are never logged (no console.* with them).
TEST        pnpm --filter extension test src/app/collab/useShare.test.ts — use renderHook (@testing-library/react) and `globalThis.fetch = vi.fn()`; reset the registry with `__resetForTests()` from doc-registry.ts and create a record with its existing `createRecord`. Cover: enable POSTs /api/rooms and persists room (getRecord shows it); enable when bound makes no request; re-render with the same docId loads the stored binding; refresh sends Authorization: Bearer <ownerToken> to /api/rooms/<id>/links; createLink prepends with token and a later refresh keeps that token; revoke DELETEs /api/rooms/<id>/links/<prefix> and removes the row; 401 → error 'Không có quyền với phòng này' and rejection; fetch throw → 'Không kết nối được máy chủ'; busy toggles. Then pnpm --filter extension typecheck.
COMMIT      feat(extension): useShare — bật chia sẻ, link xem, lưu room vào registry (8b4)
