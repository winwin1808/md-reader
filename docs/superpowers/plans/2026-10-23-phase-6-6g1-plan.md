# Plan: Phase 6 / 6g1 — render transforms as rehype plugins (before sanitize)
Author: haonq (coordinator: Claude Opus). Status: reviewed. Phase: 6. Sub-phase: 6g1
Spec: docs/superpowers/specs/2026-10-23-phase-6-design.md
Branch: phase-6-6g1-rehype-plugins
BranchPoint: 423cdf2
Why: today alerts / external links / typographer / metadata card are regex passes over
the HTML string AFTER rehype-sanitize, so whatever they emit is never sanitized and the
regexes can be steered by document content. Moving them to hast before sanitize makes the
sanitizer the last word.

INTERFACES  plugins.ts exports (unified attachers, `import type { Root } from 'hast'`):
              rehypeGithubAlerts(options: { locale: 'vi' | 'en' })
                blockquote whose first element child is a <p> whose first text starts with
                `[!NOTE|TIP|IMPORTANT|WARNING|CAUTION]` (case-insensitive) → replaced by
                <div class="markdown-alert markdown-alert-{type}" role="region" aria-label="{title}">
                  <p class="markdown-alert-title"><svg class="markdown-alert-icon" viewBox="0 0 16 16" width="16" height="16" aria-hidden="true"><path d="…"/></svg><span>{title}</span></p>
                  …the blockquote's children with the marker (and one following <br> or leading "\n") removed from the first <p>
                </div>
                Titles/icons: move ALERT_ICONS path `d` values and the vi/en title maps from
                options.ts (locale 'vi' → vi titles, anything else → en).
              rehypeExternalLinks()
                a[href^="http://" | "https://"] without class external-link → add class
                external-link, target="_blank", rel="noopener noreferrer" (replacing any
                existing target/rel), append the same external-link-icon <svg><path/></svg>
                as today.
              rehypeTypographer()
                text nodes only, skipping any node with an ancestor pre, code, kbd, script,
                style, svg; same replacements as today's replaceTypography (move it).
              rehypeMetadataCard(frontmatter: Record<string, unknown>)
                prepends <div class="markdown-metadata-card"> with one
                <div><strong>{key}</strong>: {value}</div> per entry (objects JSON.stringify,
                null/undefined → ''), text nodes only (no string HTML) — same visible output as today.
            render.ts: build the processor as remarkRehype → rehypeSlug → (rehypeRaw) →
              (rehypeHighlight) → [githubAlerts → externalLinks → typographer → metadataCard,
              each only when its option is true as today; metadataCard only when frontmatter
              has keys] → rehypeSanitize(schema) → rehypeStringify. The post-stringify string
              passes are deleted. Extend the schema (both raw and non-raw) to allow exactly what
              the plugins emit: div/p/span className markdown-alert*, role, ariaLabel;
              svg (className markdown-alert-icon | external-link-icon, viewBox, width, height,
              ariaHidden, xmlns) and path (d, fill, stroke, strokeLinecap, strokeLinejoin,
              strokeWidth); a className external-link, target, rel; div className
              markdown-metadata-card. Nothing else is widened.
            options.ts: remove applyTypographer, applyExternalLinks, applyGitHubAlerts and their
              helpers; keep processFrontmatter and escapeHtml exported.
INVARIANTS  - packages/core is pure TS: no react, no chrome.*, no document/DOM APIs.
            - Parser stays unified/remark; full re-parse, no incremental parsing.
            - rehype-sanitize is the LAST transform before stringify; nothing edits the HTML
              string after it.
            - No new runtime dependency (hast types / unist-util-visit only if already installed;
              otherwise walk the tree by hand).
TEST        pnpm --filter core test src/render
            Cases that called applyTypographer / applyExternalLinks / applyGitHubAlerts directly become
            renderToHtml(parseMarkdown(md), { <matching option>: true }) cases asserting the same visible
            markup (same classes, attributes, icon, text). Cases already using renderToHtml keep their
            assertions; if one fails only because of whitespace between tags, adjust that one and list it.
            Use a hand-written tree walk (unist-util-visit is not a declared dependency). Add: (1) `> [!NOTE]\n> <img src=x onerror=alert(1)>` with allowRawHtml false
            → output contains no `<img` and no `onerror`; with allowRawHtml true → `<img` may
            appear but no `onerror`; (2) typographer leaves "`--x--`" (inline code) untouched
            while "a -- b" becomes "a – b"; (3) a link `[x](javascript:alert(1))` with
            externalLinks true gets no target/rel and no javascript: href survives.
            Then `pnpm --filter core test`, `pnpm --filter ui test`, `pnpm -r typecheck`; report all.
COMMIT      refactor(core): alerts, links, typographer and metadata as rehype plugins before sanitize
