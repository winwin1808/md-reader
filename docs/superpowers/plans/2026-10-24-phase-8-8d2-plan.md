# Plan: Phase 8 — 8d2 Awareness wiring
Author: Hao Nguyen. Status: building. Phase: 8. Sub-phase: 8d2
Spec: docs/superpowers/specs/2026-10-24-phase-8-design.md
Branch: phase-8-8d2-awareness
BranchPoint: 38960c4

Goal: on both the extension app page and the web edit page, the room's awareness drives the toolbar avatars (PresenceBar) and the remote cursors in the Editor. Each person publishes `{ name, color, colorLight }`. The first local edit while bound to a room records `clientID → name` in `meta.actors` through the existing core `registerActor`.

Decisions (deviations from the spec FILES line, recorded here):
- `awarenessToPeers` and `usePeers` live in `packages/ui` (`src/components/presence.ts`), not in apps/extension. Both apps need them, and they are pure functions/React that take a duck-typed awareness with no provider import, so ui is the right layer.
- "First local edit" is detected in core with `trackLocalActor(doc, getName)`, which watches `afterTransaction` for `tr.local` transactions that change `Y.Text "source"`. Provider and IndexedDB updates arrive through applyUpdate (local = false), so core never needs to know the provider.
- Avatar colour comes from `peerColor(clientId)` locally. A remote peer's own `user.color` string is never put into our PresenceBar styles. Remote names are trimmed and capped at 40 chars, falling back to "Ẩn danh".
- `colorLight` is set explicitly to `color-mix(in srgb, <color> 20%, transparent)`, because y-codemirror.next's default (`color + '33'`) breaks for `var(--peer-N)`.

            export interface AwarenessLike { clientID: number; getStates(): Map<number, Record<string, unknown>>; on(ev: 'change', cb: () => void): void; off(ev: 'change', cb: () => void): void }
            export function awarenessToPeers(states: Map<number, Record<string, unknown>>, selfId: number): Peer[]
            export function usePeers(awareness: AwarenessLike | null | undefined): Peer[]
            export function peerUser(clientId: number, name: string): { name: string; color: string; colorLight: string }
BEHAVIOR    - awarenessToPeers yields one Peer per state that has a `user` object.
            - Fields: name = String(user.name ?? '').trim().slice(0, 40) || 'Ẩn danh'; color = peerColor(clientId), never the remote string; isSelf = clientId === selfId.
            - States without `user` are skipped.
            - Self is included when its state has a user.
            - peerUser returns { name, color: peerColor(clientId), colorLight: `color-mix(in srgb, ${color} 20%, transparent)` }.
            - usePeers subscribes to 'change' on mount and whenever the awareness object changes, recomputes with awareness.clientID as selfId, and unsubscribes on cleanup. A null awareness returns [].
INVARIANTS  - packages/ui is React. It never uses chrome.* and never imports a Yjs provider or y-protocols; the awareness is duck-typed (AwarenessLike).
            - Names are user-supplied and only ever rendered as text.
            - No new dependencies in packages/ui/package.json.

            - a remote `user.color = 'red;background:url(x)'` is ignored in favour of peerColor
            - peerUser's colorLight contains color-mix and the var
            - usePeers with a small fake awareness (Map plus listeners): renders the initial peers, re-renders on emitting 'change', unsubscribes on unmount, and returns [] for null
