# Plan: Phase 8 — 8c2 Edit mode on the web
Author: Hao Nguyen. Status: built. Phase: 8. Sub-phase: 8c2
Spec: docs/superpowers/specs/2026-10-24-phase-8-design.md
Branch: phase-8-8c2-web-edit
BranchPoint: 0af89ef

Goal: opening an edit link (`/s/<token>` whose role resolves to `edit`) asks for a display name once,
then shows the ui `Editor` + `FormattingToolbar` next to a live preview, bound to the room through
y-partyserver. View links never show the editor. The web page has no disk access and no export.

Decisions recorded here:
- `apps/web/src/collab.ts` is a twin of `apps/extension/src/app/collab/bindRoom.ts` (same signature,
  same status machine including the 8c1a.4 fixes). Two apps cannot share it: `packages/core` may not
  import a provider, and `packages/ui` stays provider-free too.
- The edit page uses a fresh `Y.Doc({ gc: false })` and lets the provider fill it. It does not apply
  the HTTP snapshot to that doc. The editor shows a loading line until status is 'online' the first
  time, so a user never types into an empty doc that hasn't received the room yet.
- Server URL on the web is `location.origin` (the Worker serves both /s/ and /parties/).
- `Editor` has no `awareness` prop yet. Remote cursors and presence arrive in 8d1/8d2; 8c2 passes none.
- Preview re-renders the whole text with `renderShareHtml` on a 120 ms debounce, same options as the
  read-only page.

### [x] 8c2.2 — EditPage: name prompt, editor and live preview
FILES       apps/web/src/EditPage.tsx (new) · apps/web/src/EditPage.test.tsx (new) · apps/web/src/SharePage.tsx · apps/web/src/SharePage.test.tsx
INTERFACES  consumes `bindRoom`, `RoomConnection`, `SyncStatus` from `./collab` (8c2.1); `renderShareHtml(text): string` from `./share-client`; `ResolveTokenResponse { roomId; role: 'view'|'edit'; title }` from `@md-reader/core`; from `@md-reader/ui`: `Editor` (props: yText, undoManager?, editorViewRef?, ...), `FormattingToolbar` (props: onAction(action: FormatAction), canUndo?, canRedo?, onUndo?, onRedo?), `applyFormat` (markdown-commands; see how apps/extension/src/app/App.tsx ~L271-301 uses it with an EditorView), `SplitViewContainer` (props: mode: 'reading'|'editor'|'split', editor, preview), `Viewer`.
            produces:
            export interface EditPageProps { token: string; info: ResolveTokenResponse; serverUrl?: string; bind?: typeof bindRoom }
            export function EditPage(props: EditPageProps): JSX.Element
BEHAVIOR    - Name: read `localStorage['mdr.displayName']` (try/catch; storage may throw). If missing/blank, show a form "Tên của bạn" (input, maxLength 40, required) + button "Bắt đầu sửa"; on submit store the trimmed name (try/catch) and continue. Never bind before a name exists.
            - Then: `doc = new Y.Doc({ gc: false })`, `yText = doc.getText('source')`, `undo = new Y.UndoManager(yText)`, `conn = (props.bind ?? bindRoom)(doc, { serverUrl: props.serverUrl ?? location.origin, roomId: info.roomId, token, name })`. Subscribe status$.
            - Until the first 'online': show "Đang tải tài liệu…" instead of the editor. After that keep the editor mounted even if status goes offline; show the status as text: Đang kết nối / Đã đồng bộ / Ngoại tuyến (role="status").
            - Layout: FormattingToolbar above `SplitViewContainer mode="split"` with editor = `<Editor yText undoManager editorViewRef />` and preview = `<Viewer html isAppPage={false} />` where html = renderShareHtml(yText.toString()) recomputed on yText changes with a 120 ms debounce.
            - FormattingToolbar onAction applies `applyFormat` through the EditorView the same way the extension App does. Undo/redo use the UndoManager.
            - No save, no export, no file access anywhere on this page.
            - Unmount: unsubscribe, conn.destroy(), undo.destroy(), doc.destroy().
            SharePage.tsx: when state is ready and `info.role === 'edit'`, render `<EditPage token={token} info={state.info} />` instead of the read-only Viewer. View role unchanged.
INVARIANTS  - apps/web has no chrome.*; cross-package imports by workspace name only.
            - Parser is unified/remark through core (renderShareHtml); full re-parse with a 120 ms debounce, no incremental parsing.
            - The Y.Doc schema is Y.Text "source"; the page never writes to Y.Map "meta" or Y.Array "history" in 8c2.
            - Tokens never logged or put in the doc.
            - UI copy is Vietnamese. Existing SharePage tests must pass unchanged.
