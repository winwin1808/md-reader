### [x] 10m.2 — App page: `update_doc` + chờ session + bắt lỗi executor
FILES       apps/extension/src/app/bridge-executor.ts · apps/extension/src/app/bridge-executor.test.ts · apps/extension/src/app/App.tsx
INTERFACES  Tiêu thụ: `applyTextChange(yText, next, origin?) => boolean` và `CheckpointTracker` (`flush(label, actor, opts?: { force?: boolean })`) từ
            `@md-reader/core`; `textHash`, `UpdateDocArgs { docId; markdown; baseHash }`, `UpdateDocResult { hash }` từ `@md-reader/core/bridge`.
            ```ts
            export const ORIGIN_MCP = 'mcp'
            export const AI_CHECKPOINT_LABEL = 'AI: cập nhật'
            export interface ExecSession { docId: string; title: string; yText: Y.Text; shared: boolean; synced: boolean; checkpoints: CheckpointTracker | null }
            // createBridgeExecutor giữ chữ ký cũ (get, opts?: { waitMs; pollMs; sleep })
            ```
            Thay đổi hành vi:
            - Chờ: `get()` trả null cũng coi như "chưa sẵn sàng" — chờ trong cùng vòng `waitMs` như `!synced`; hết giờ mà vẫn null → `NOT_FOUND`
              'document is not open in this tab'; hết giờ mà chưa synced → `TIMEOUT` như cũ. Session có docId KHÁC args.docId → `NOT_FOUND` ngay.
            - update_doc (sau khi chờ xong, dùng session MỚI NHẤT): `cur = yText.toString()`; `await textHash(cur) !== baseHash` → `CONFLICT`
              'document changed since baseHash; current hash <hash>' (agent gọi lại get_doc). Khớp → `checkpoints?.flush('auto', 'Bạn')` (khép sửa
              tay đang dở của người dùng), `changed = applyTextChange(yText, markdown, ORIGIN_MCP)`, nếu `changed` → `checkpoints?.flush(AI_CHECKPOINT_LABEL,
              'AI', { force: true })`. Kết quả `{ hash: await textHash(yText.toString()) }`.
            - share_doc / list_links / revoke_link vẫn `INTERNAL` 'not implemented yet' (10n).
            App.tsx: `execSessionRef` thêm `checkpoints: session.checkpoints ?? null`; listener EXEC đổi thành
            `exec(m.req).then(sendResponse, (err) => sendResponse({ type: 'res', id: m.req.id, ok: false, error: { code: 'INTERNAL', message: String(err) } }))`
            — giữ nguyên kiểm `sender.id === chrome.runtime.id && !sender.tab`.
            Test bridge-executor.test.ts (viết trước, Y.Doc thật tạo bằng `createDoc`/`ensureDoc` của core, tracker thật `createCheckpointTracker`):
            (1) đổi đúng một từ → quan sát `yText.observe` thấy delta chỉ 1 delete + 1 insert, transaction origin `'mcp'`, hash trả về = textHash text mới;
            (2) hội tụ: replica B (Y.Doc thứ hai, đồng bộ qua `Y.encodeStateAsUpdate`/`Y.applyUpdate`) sửa đoạn cuối trong khi A nhận update_doc
                sửa đoạn đầu → sau khi trao đổi update hai bên, cả hai text bằng nhau và chứa cả hai sửa;
            (3) baseHash sai → CONFLICT, text không đổi, message chứa hash hiện tại;
            (4) history có thêm entry label 'AI: cập nhật' actor 'AI'; markdown y hệt → không thêm entry 'AI: cập nhật';
            (5) get() null rồi có session sau 2 lần poll → get_doc trả đúng; luôn null → NOT_FOUND.
            Các test cũ cập nhật thêm `checkpoints: null`.
INVARIANTS  Mọi ghi `Y.Text` đi qua `applyTextChange` (delta nhỏ nhất) — cấm xoá toàn bộ rồi chèn lại.
            Y.Doc là nguồn sự thật; không đổi schema (`Y.Text "source"`, `Y.Map "meta"`, `Y.Array "history"`), không tăng `formatVersion`.
            Checkpoint ghi qua `CheckpointTracker.flush` (có `clientIds` + snapshot) — không push thẳng vào `history`.
            Chỉ `apps/extension` dùng `chrome.*`; App.tsx chỉ đổi ref session + nhánh lỗi của listener; test App.test.tsx xanh nguyên.

### [x] 10m.3 — core: ghi Y.Text dưới một clientID riêng (tác giả AI)
FILES       packages/core/src/doc/apply-as.ts · packages/core/src/doc/apply-as.test.ts · packages/core/src/index.ts
INTERFACES  Tiêu thụ trong core: `applyTextChange` (./apply.js), `registerActor` (./checkpoint.js), `getSource` (./doc.js), `createDoc` cho test.
            ```ts
            /** Áp `next` vào source của `doc` như một client khác (clientID mới, ngẫu nhiên do Yjs cấp), ghi `actor` vào meta.actors
             *  cho clientID đó, rồi đưa đúng phần cập nhật về `doc` bằng `Y.applyUpdate(doc, update, origin)`. Trả false nếu text không đổi. */
            export function applyTextChangeAsActor(doc: Y.Doc, next: string, actor: string, origin?: unknown): boolean
            ```
            Cách làm: `fork = new Y.Doc({ gc: false })`; `Y.applyUpdate(fork, Y.encodeStateAsUpdate(doc))`; `sv = Y.encodeStateVector(doc)`;
            nếu `getSource(fork).toString() === next` → `fork.destroy()`, false. Ngược lại `registerActor(fork, actor)`; `applyTextChange(getSource(fork), next)`;
            `Y.applyUpdate(doc, Y.encodeStateAsUpdate(fork, sv), origin)`; `fork.destroy()`; true. Export từ `packages/core/src/index.ts`.
            Test (viết trước, đỏ): text sau = next; đổi một từ → `doc` nhận đúng 1 transaction origin như truyền, các item mới có clientID ≠ `doc.clientID`;
            `meta.actors` map clientID mới → actor; text y hệt → false, không có transaction; doc `formatVersion` và history không đổi; một replica khác
            sửa đồng thời đoạn khác vẫn hội tụ (trao đổi update hai chiều).
INVARIANTS  `packages/core` thuần TS — được dùng yjs, KHÔNG react / `chrome.*` / `document`, không biết provider nào đang chạy.
            Mọi ghi `Y.Text` qua `applyTextChange` (delta nhỏ nhất) — cấm xoá toàn bộ rồi chèn lại.
            Không đổi schema (`Y.Text "source"`, `Y.Map "meta"`, `Y.Array "history"`), không tăng `formatVersion`. Doc dùng `gc:false`.
TEST        pnpm --filter core test src/doc/apply-as.test.ts   (+ `pnpm --filter core typecheck`)
COMMIT      feat(core): applyTextChangeAsActor ghi text dưới clientID riêng

### [x] 10m.4 — App page: update_doc an toàn (kiểm lại text, tác giả AI, chờ checkpoints, chờ IDB ghi xong)
FILES       apps/extension/src/app/bridge-executor.ts · apps/extension/src/app/bridge-executor.test.ts · apps/extension/src/app/App.tsx · apps/extension/src/app/hooks/useDocSession.ts
INTERFACES  Tiêu thụ `applyTextChangeAsActor(doc, next, actor, origin?)` từ `@md-reader/core` (10m.3).
            ```ts
            export interface ExecSession { docId; title; yText: Y.Text; shared; synced; checkpoints: CheckpointTracker | null;
                                           persisted: (() => Promise<void>) | null }
            ```
            - update_doc: sẵn sàng = `synced && checkpoints !== null` (chờ trong cùng vòng `waitMs`; hết giờ → TIMEOUT). get_doc vẫn chỉ cần `synced`.
            - Sau `await textHash(cur)` so khớp baseHash, kiểm lại ĐỒNG BỘ `s.yText.toString() === cur`; khác → `CONFLICT` (message chứa hash
              text hiện tại). Từ lần kiểm này tới lúc ghi không được có `await`.
            - Ghi bằng `applyTextChangeAsActor(s.yText.doc!, markdown, 'AI', ORIGIN_MCP)` thay cho `applyTextChange` (yText.doc null → INTERNAL).
              Giữ `checkpoints.flush('auto','Bạn')` trước và `flush(AI_CHECKPOINT_LABEL, 'AI', { force: true })` sau khi changed.
            - Sau khi ghi: `await Promise.race([s.persisted?.() ?? Promise.resolve(), sleep(2000)])` rồi mới trả `{ hash }`.
            useDocSession.ts: thêm `persisted(): Promise<void>` vào giá trị trả về — mở một transaction `readonly` trên store `'updates'` của
            `db` của y-indexeddb hiện tại (IDB xếp nó sau transaction ghi đang chờ nên `oncomplete` = các update trước đó đã commit); resolve ở
            `oncomplete`/`onerror`/`onabort`; không có persistence/db → resolve ngay. App.tsx: `execSessionRef` thêm `persisted: session.persisted ?? null`.
            Test (sửa trước, đỏ): (a) text đổi trong lúc `textHash` await (chèn edit qua microtask trước khi hash xong — dùng doc thật, mock `textHash`
            nếu cần bằng vi.mock module '@md-reader/core/bridge' giữ nguyên các export khác) → CONFLICT và edit chen ngang còn nguyên;
            (b) sau update_doc, các item mới trong source có clientID ≠ `doc.clientID` và `meta.actors` của clientID đó = 'AI';
            (c) `synced: true, checkpoints: null` rồi có checkpoints sau 2 poll → update áp dụng + có entry 'AI: cập nhật'; luôn null → TIMEOUT, text không đổi;
            (d) `persisted` được await trước khi trả (promise giả resolve muộn → response chưa về trước đó); persisted treo → vẫn trả sau sleep(2000) giả.
INVARIANTS  Mọi ghi `Y.Text` qua `applyTextChange`/`applyTextChangeAsActor` — cấm xoá toàn bộ rồi chèn lại.
            Không đổi schema Y.Doc, không tăng `formatVersion`; checkpoint chỉ qua `CheckpointTracker.flush`.
            Chỉ `apps/extension` dùng `chrome.*`; useDocSession chỉ thêm `persisted`, không đổi hành vi khác; App.test.tsx xanh nguyên.
            Lệnh ghi không được gửi/áp hai lần cho cùng một request.
