### [x] T1 — Thứ tự xoá an toàn + kiểm kết quả purge
parallel-group: 11d
FILES       apps/api/src/api.ts · apps/api/src/index.ts · apps/api/src/api.test.ts · apps/api/src/index.test.ts
INTERFACES  - `export type DeleteOutcome = 'deleted' | 'not_found' | 'purge_failed'`;
              `deleteRoomEverywhere(roomId, d): Promise<DeleteOutcome>` (chữ ký `d` giữ nguyên).
            - Thứ tự mới: (1) `d.purge?.(roomId)` — ném → return 'purge_failed' (KHÔNG chạm D1); (2) `d.assets?.deleteRoom(roomId)` — ném → 'purge_failed';
              (3) `d.limits?.forgetRoom` — ném → chỉ console.error; (4) `ok = await d.store.deleteRoom(roomId)`; (5) `forgetRoomAuth(roomId)`; return ok ? 'deleted' : 'not_found'.
            - Owner route: 'purge_failed' → 502 `{ error: 'PURGE_FAILED' }`; 'not_found' → 404; 'deleted' → 204.
            - Admin takedown: 'purge_failed' → 502 `{ error: 'PURGE_FAILED' }` và KHÔNG `addTakedown`; 'not_found' → 404; 'deleted' → addTakedown + 204.
            - index.ts purge wire: response null hoặc `!res.ok` → `throw new Error('purge ' + status)` (bỏ `.then(() => undefined)`).
INVARIANTS  - Chỉ owner (isOwner) hoặc admin (adminSecret) xoá được — giữ nguyên các check trước khi gọi deleteRoomEverywhere.
            - Purge DO idempotent (tombstone) → gọi lại sau 502 an toàn; D1 chỉ bị xoá khi purge + assets thành công để chủ còn quyền thử lại.
            - Client không tự đặt `x-mdr-internal`; không chạm máy chủ thật.
TEST        pnpm --filter api test src/api.test.ts src/index.test.ts (đỏ trước: (a) purge ném → owner DELETE 502, `store` còn phòng + link, gọi lại khi purge ổn → 204 và
            phòng mất; (b) assets.deleteRoom ném → 502, D1 còn; (c) limits ném → vẫn 204; (d) admin takedown purge ném → 502, addTakedown không gọi;
            (e) index: DO trả 500 cho /purge → owner DELETE 502). Sửa test cũ kỳ vọng thứ tự/boolean cũ. Sau đó `pnpm --filter api test` xanh.
COMMIT      fix(api): xoá phòng purge trước, kiểm kết quả, 502 thử lại được (11d)
